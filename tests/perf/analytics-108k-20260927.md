# 首期分析接口 108k Check 本机压测

日期：2026-09-27（北京时间）  
依据：父 PRD §9.3。以下是隔离库合成数据的实测结果，不代表生产环境容量。

## 环境与数据

- 宿主机：MacBookPro18,2，Apple M1 Max，10 核，64 GB 内存；API 在宿主机以 .NET 10 Debug 构建运行。
- MySQL：Docker VM 约 16 GiB，MySQL 8.4.11 arm64，InnoDB buffer pool 128 MiB。
- 隔离库：`jogeoai_perf_20260927`，按 001–007 migration 建表；90 Run、540 Target、108,000 Check、540,000 原始引用、540,000 派生外部引用事件、108,000 搜索词事件、756,000 词项事实。API 响应中的窗口 `checkCount=108000`、`eligibleChecks=108000`、`externalCitationEvents=540000`、`queryEvents=108000`。
- 代表性 `EXPLAIN`：Check 窗口读取走 `uq_visibility_checks_tenant_id` 后关联 `analytics_check_arrivals.uq_analytics_arrival_check`、`analysis_check_work.PRIMARY`、`check_analysis.PRIMARY`；引用读取接着走 `citation_events.PRIMARY`、`citation_classifications.PRIMARY`。Check 窗口排序显示 `Using filesort`。007 另建 `ix_query_key`、`ix_query_included`、`ix_query_terms_term`、`ix_citation_url`、`ix_citation_domain` 等索引供明细定位。以上是本次隔离库执行计划，不保证其他数据分布选择相同索引。

## 方法与结果

以 `tests/perf/seed_analytics_108k.sql` 建立数据，独立 API 监听 5269，固定一次 Overview 返回的 `snapshotToken`。`tests/perf/measure_analytics_http.py` 为每个入口先串行预热 10 次，再发起 40 个请求、最大 10 并发，统计最近秩 P95。筛选为 UTC 最近 90 天，所有请求只读；5260 上已有 API 未参与。

| 入口 | P50 | P95 | PRD 目标 |
|---|---:|---:|---:|
| Overview | 884.66 ms | 1,044.07 ms | ≤2,000 ms |
| Visibility | 1,116.99 ms | 1,281.20 ms | ≤2,000 ms |
| Share of Voice | 894.49 ms | 1,003.58 ms | ≤2,000 ms |
| Prompt 列表 | 48.90 ms | 61.63 ms | ≤2,000 ms |
| Query Fan-Out | 277.68 ms | 375.48 ms | ≤2,000 ms |
| Citations | 591.53 ms | 973.63 ms | ≤2,000 ms |
| Check 详情 | 10.24 ms | 25.74 ms | ≤500 ms |

全部被测入口达到预热 P95 目标。缓存前相同脚本测得 Overview 14.73 秒、Visibility 13.53 秒、SOV 13.70 秒、Prompt 列表 12.30 秒、Fan-Out 3.29 秒、Citations 11.39 秒的 P95；这两轮不是同一时刻的严格 A/B 实验，仅用于说明优化动机。

最终版本另外测量引用变化：当前 45 天与前一等长 45 天均有合成引用，`minimumEvents=1`、`limit=50`，先串行预热 10 次，再发起 40 次请求、最大 10 并发。`citations/changes` 的 P50 **124.93 ms**、P95 **158.38 ms**、最大 **169.16 ms**，达到 2,000 ms 目标。不同页长的实库校验中，`limit=50` 的前四页与 `limit=100` 的前两页得到相同顺序的 200 个不同 URL/域名键；每页有界，改阈值复用游标返回 `INVALID_CURSOR`，`limit=101` 返回 `INVALID_LIMIT`。此前尚未分页的比较窗口曾测得 P95 约 3.14 秒；请求合同与缓存已变化，不能把两轮视为严格 A/B 测试。

URL 全榜和域名下钻在最终分页实现上另测 90 天窗口，均为预热 10 次、40 请求、10 并发：

| 入口 | P50 | P95 | 最大值 |
|---|---:|---:|---:|
| 全站 URL 榜首 50 条 | 98.46 ms | 128.33 ms | 155.35 ms |
| `perf-1.example.test` 域名 URL 榜首 50 条 | 199.08 ms | 293.01 ms | 317.39 ms |
| 同域名详情（内联 100 URL、50 条 Check 证据） | 758.39 ms | 874.65 ms | 991.69 ms |

每个 URL 榜页从缓存的固定快照排序键中选取，随后只为本页 URL 构造聚合行；域名筛选不改变全站引用事件的份额分母。此前全站榜在无此优化时一次首读约 4.4 秒；最终版本一次未预热的域名详情约 4.38 秒，因此这些 P95 只证明 PRD 要求的预热表现，不证明冷读也低于 2 秒。

API 单例仓储按快照令牌缓存 Check 事实、前期指标，以及当前窗口的搜索词/引用/Google/词项事实；最多保留两个快照，令牌 15 分钟过期。变化接口分别缓存前期窗口事实和两窗口的轻量 URL/域名聚合，只为当前页收集 Check ID 和生成证据路径，不覆盖当前窗口缓存。URL 榜还缓存排序键，失败的加载任务会从缓存移除。最终 URL 榜与域名详情测量后 API 进程 RSS 约 3.08 GiB；此前多轮入口压测后的另一进程曾为约 3.34 GiB。RSS 包含运行时保留内存和累计分配，不能直接视为缓存净占用，也不能将不同进程的两次读数作严格内存对比。多站点或多筛选并发可能使有限缓存频繁换出，且没有分布式复用；本次只验证一个站点、一组筛选、无采集写入时的预热延迟。生产内存上限未在 PRD 中给出目标，需在部署容量评估中单独考虑。

复测命令：`PERF_API_BASE=http://127.0.0.1:5269 PERF_SITE_ID=<隔离站点> PERF_TENANT_ID=<隔离租户> PERF_CHECK_ID=<隔离 Check> python3 tests/perf/measure_analytics_http.py`。引用变化单项加 `PERF_WINDOW_DAYS=45 PERF_ENDPOINTS=citationChanges PERF_CHANGE_MINIMUM_EVENTS=1 PERF_CHANGE_LIMIT=50`；URL 榜单项加 `PERF_ENDPOINTS=citationUrls PERF_URL_LIMIT=50`，域名榜再加 `PERF_URL_DOMAIN=perf-1.example.test`。脚本不清理测试数据；删除隔离库须按项目指引先列明对象并取得确认。
